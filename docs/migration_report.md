# SOR2XCombo → Godot 迁移:评估报告与迁移方案

> 作者:iintothewind(评估日期 2026-08)
> 背景:SOR2XCombo(OpenBOR 3.0 Build 6392 MOD)将固定于 BOR3 收尾;本报告评估其资产向 **Godot 4.x** 新项目迁移的可复用性,并给出完整迁移方案。
> 配套文档:`docs/migration_schema.md`(数据转换规格)、`docs/migration_architecture.md`(Godot 架构映射)、`docs/migration_pipeline.md`(导入管线)。

---

## 1. 结论摘要

- **可复用**:全部**设计/数值/数据层**——系统设计文档、角色五维属性、难度预设、484 个角色 txt 中的招式/帧/判定数据(约 18 万行,机械可转换)
- **不可复用**:OpenBOR 脚本行为代码(47k 行)与引擎耦合,需按规则重写;素材(8588 PNG + 768 音频)版权不属于作者,**不建议迁移**(详见 §3)
- **总体判断**:数据层自动转换(转换器 1-2 周)+ 行为层重写(核心战斗 4-8 周 + 每角色 2-4 周)是可行路径;战斗系统规则(OTG/Juggle/Rush Heat/Last Chance)已全部核实为纯函数式逻辑,可单元测试,迁移风险可控

|---|---|---|---|---|---|

## 3. 版权风险(重要)

README 明确声明:SOR2XCombo 的素材(图片/音频)均来自互联网,**版权不属于作者**;作者仅拥有自己写的代码。因此:
- 素材用于新项目**仅限个人学习**,不得发布/商用
- 新项目应使用自备或授权素材;本方案的所有数据/设计迁移不涉及素材版权

### 3.1 可带走 / 不可带走清单(作者决策,2026-08 确认)

**带不走(版权在 SEGA/素材原作者手中)**:
- 角色形象与设计(Adam/Axel/Blaze/Max 等 SOR 角色本身)
- 动画素材(8588 张帧图,无论是否重绘)
- 音乐/音效(676 wav + 92 ogg)
- 招式的**表现层**(动作造型、特效演出、标志性招式名)——与角色动画绑定,换皮抄袭只会成为"廉价替代",玩家不买账

**能带走(作者原创劳动,无版权问题)**:
- **战斗系统机制**:弹反收益体系、Rush Heat、Last Chance、Juggle/OTG 消耗制、难度联动预设、防御槽/能量槽双资源
- **招式数据层**:攻击判定框(attack 十参数)、取消链(cancel 表)、指令序列(com)、连段派生结构、角色五维平衡数值——README 声明"调整了几乎所有招式的性能",这些是作者劳动成果
- **连段手感**:取消节奏、判定帧、硬直时长——SOR2XCombo 独有,原版 SOR2 无此体系

### 3.2 项目定位(新项目立项原则)

- **廉价替代不可取**:换造型抄原招式 = 既无原版号召力又无原创价值,两头不讨好
- **核心资产是"手感"而非"招式造型"**:机制(思想/表达二分法中不受保护)+ 手感参数照搬,角色/动画/招式名全部原创
- **招式模板化策略**:把已验证的招式抽象为功能性模板(突进上勾拳型/升龙型/投技型/保险技型/必杀型),新角色从模板库选招式 + 原创动画 + 调平衡——保留全部验证过的手感,产出完全原创作品
- **卖点表述**:连段取消体系与系统深度是 SEGA 原版与 SOR4 都没有的,这是新作品的差异化核心竞争力

## 4. 数据转换方案(详见 migration_schema.md)

- 转换器:Python 3.10+ 标准库,输出 `chars.json`
- 五类解析规则:##MAIN 头部字段、anim 块、attack{1-10} 十参数、cancel/com 指令序列、行为钩子剥离
- 已用 axel.txt 82 个命令验证覆盖度 100%;`@cmd` 约 100 个行为函数与 2789 处脚本钩子引用标记为 `behaviors` 不转换
- 关键语义已核实:attack 十参数(x/y/宽/高/伤害/击倒/可格挡/闪光/暂停/z)、delay 厘秒→毫秒、attack# 编号决定受击动画

## 5. Godot 架构映射(详见 migration_architecture.md)

- 角色 = 状态机(`CharacterStateMachine`)+ `CancelTable` + `Area2D` 判定框
- 核心系统映射(均已对照 OpenBOR 实现核实):
  - **OTG**:受击时若动画为 FALL/BURN/SHOCK 且 frame≥1 则扣 otgpoints(takedamage/main.c `otg()`)
  - **Juggle**:jugglepoints/jugglecost 实体变量消耗
  - **Rush Heat**:rush_count ≥ 阈值(5/7/9/11/13/15)→ 无敌(ondoattack/main.c `rushHeat()`)
  - **Last Chance**:致命伤害 + hp<10%max + gp≥50%max(或 gp=100%)→ 回血(takedamage/main.c `lastChance()`)
  - **难度联动**:Normal/Hard/Mania 三档预设已提取(normal=juggle unlimited/otg unlimited/rushHeat 5;hard=40/6/7;mania=30/4/9+blockCost 1+smarterEnemy on)
- 输入:Godot `InputBuffer` 匹配 JSON commands 指令表(d f a2 / f f a2 / a2+s 等)

## 6. 导入管线(详见 migration_pipeline.md)

- 图片:8-bit 调色板 PNG 批转 RGBA(8584/8588 张),SpriteFrames/帧表,offset 锚点换算
- 音频:wav 统一 16-bit/44100,音量 0-60→0-1,AudioStreamPlayer 池
- 数值:3 张表(五维/难度/默认配置)手工转录为 .tres/JSON
- 重写顺序:战斗管线 → 输入 → 状态机 → 防御/投技 → 纯规则系统(可单测)→ 关卡/菜单/存档

## 7. 路线图(建议)

1. **阶段 A(2-3 周)**:转换器 + golden 测试(axel/shiva/kun)→ chars.json
2. **阶段 B(1-2 周)**:Godot 项目骨架 + 数据加载器 + 状态机框架
3. **阶段 C(4-8 周)**:核心战斗系统重写(含 5 个纯规则系统的单元测试)
4. **阶段 D(2-4 周/角色)**:角色行为重写,先完成 Axel 验证全流程
5. **阶段 E(4-6 周)**:关卡/菜单/存档/难度联动
6. 里程碑:阶段 C 结束时应有"单角色可打沙袋"的可玩验证

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 行为代码重写量大(47k 行) | 数据驱动 + 纯规则单测;@cmd 100 函数按语义分类复用 |
| 手感差异(帧/物理换算) | 保留 3.0 引擎做行为对照;offset/delay 精确换算 |
| 素材版权 | 新项目用自备素材,仅迁移数据 |
| 8-bit PNG 转换质量 | 批转后视觉抽查;palette swap 用 shader 保真 |
